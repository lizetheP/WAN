!-------------------------------------------------------------------------------
! Mejores prácticas para el diseño de listas de control de acceso “Extendidas”
!-------------------------------------------------------------------------------
! 1. Identificar la fuente/origen (tráfico fuente) y el destino.
! 2. Trazar el trayecto del tráfico NO permitido. 
! 3. Trazar el trayecto del tráfico permitido. 
! 4. Identificar el router donde se instalará la lista de control de acceso.
! 5. Identificar la interfaz donde se va a asociar la lista de control de acceso.
! 6. Escribir la ACL, instalarla y probarla.

! NOTA: Realizar pruebas de conectividad antes y después de instalar una ACL

REGLA: LAS LISTAS DE CONTROL DE ACCESO EXTENDIDAS SE DEBEN INSTALAR LO MAS CERCA DEL ORIGEN, PARA EVITAR QUE EL TRÁFICO LLEGUE A LUGARES DONDE NO SE NECESITE LLEGAR.

Estándar 1 - 99
Extendidas 100 - 199

!------------------------------------------------------------
! Ejercicio 1
!------------------------------------------------------------

1. Diseña una lista de control de acceso extendida para impedir que las computadoras de la subredes de Profesores y Alumnos tengan acceso a la subred de Directores.

access-list 101 remark Permitir respuestas de retorno a Profesores y alumnos desde Directores
access-list 101 permit ip 132.254.89.192 0.0.0.31 any:
! Permite que la subred de Directores pueda salir hacia cualquier destino.

access-list 101 permit tcp any 132.254.89.192 0.0.0.31 established
! El parámetro established permite que paquetes TCP entren a la red de Directores solo si son parte de una sesión 
! que el Director ya inició previamente.

access-list 101 permit icmp any 132.254.89.192 0.0.0.31 echo-reply:
! Permite que los Directores reciban respuestas de "Ping" (echo-reply). Si un Director hace ping a un Alumno, 
! esta línea permite que la respuesta regrese.

!------------------------------------------------------------


!------------------------------------------------------------
!Ejercicio 2
!------------------------------------------------------------

2. Diseña una lista de control de acceso extendida para que el visitante 1 no pueda acceder a la subred de Servidores

! Asegura de que si un Servidor intenta contactar al Visitante 1, la respuesta pueda pasar.
access-list 102 remark Permitir trafico de retorno a Visitante1 desde Servidores
access-list 102 permit ip 132.254.89.128 0.0.0.63 any
! Permite que la subred de Servidores envíe tráfico hacia cualquier destino.

access-list 102 permit tcp any 132.254.89.128 0.0.0.63 established
! Permite paquetes TCP de vuelta hacia los servidores, siempre y cuando la conexión haya sido iniciada 
! originalmente por un servidor (gracias al parámetro established).

access-list 102 permit icmp any 132.254.89.128 0.0.0.63 echo-reply
! Permite que los servidores reciban respuestas de Ping (echo-reply) desde cualquier lugar.

!------------------------------------------------------------


!------------------------------------------------------------
!Ejercicio 3
!------------------------------------------------------------

3. Diseña una lista de control de acceso extendida para impedir que las computadoras de la subred de Profesores tengan acceso al servidor de Directivos.

access-list 103 remark Permitir trafico de retorno a Profesores desde Server Directivos
access-list 103 permit ip host 132.254.89.221 any
! Permite que el Servidor de Directivos envíe cualquier tipo de tráfico IP hacia cualquier destino.

access-list 103 permit tcp any host 132.254.89.221 established
! Permite que entren paquetes TCP al servidor solo si son parte de una conexión que el servidor inició primero.

access-list 103 permit icmp any host 132.254.89.221 echo-reply
! Permite que el servidor reciba las respuestas de los Pings que él mismo realice.

access-list 104 permit tcp any host 132.254.89.238 established
